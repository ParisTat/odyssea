## Context

You and a dev friend want a site to plan trips together, and both of you will push code to it. It has to work for every future trip, not only Paris.
Your choices:
- **Name:** `odyssea`, published at `paristat.github.io/odyssea/`. The 404 page reads "404: Home Not Found".
- **Trips:** the homepage shows one active trip, and a header dropdown switches to another. A `/trips` page shows a card for every trip, past and current, and each card opens that trip.
- **Each trip has** a day-by-day itinerary, a shared budget and a page of practical info.
- **Money:** everything is totalled in EUR. An expense in another currency stores the rate used when it was added, taken from the Frankfurter (ECB) API. A live converter shows today's rate.
- **Languages:** the code supports several languages from the start (i18next), but only English text exists for now. Translations could move to Firebase later.
- **Data:** JSON files in the repo for now. Firebase may come later, possibly with some parts behind a login.
- **Visibility:** public site. It shows no exact address, only the area.
- **Repo:** a new public GitHub repo. Your friend becomes a collaborator; you'll give me their username later.

For Paris: you want to stay inside the Boulevard Périphérique (arrondissements 1–20). The trip's Info page gets a "Where to stay" section about this.

**Target repo:** a new folder, `repos/odyssea/`, with its own git repo. No existing repo is touched apart from one row in the workspace `CLAUDE.md` Repos table.

## Routes

| Route | Shows |
|---|---|
| `/` | The **active trip**: the trip happening now, else the next upcoming one, else the most recent one |
| `/trips` | A card for every trip (upcoming, current, past), each linking to that trip |
| `/trips/:slug` | That trip's itinerary |
| `/trips/:slug/budget` | That trip's budget |
| `/trips/:slug/info` | That trip's practical info |
| `*` | "404: Home Not Found" |

The header has a trip dropdown that navigates to `/trips/:slug`, plus tabs for Itinerary, Budget and Info.

How the design leaves room to grow:
- **Moving to Firebase later:** add `firebaseTripRepository.ts` (and an i18next Firebase backend), then change one line where the repository is chosen.
- **Adding a trip:** add a new folder under `data/trips/`. No code change is needed.
- **Translating content:** trip text fields use `LocalizedText = { en: string; [locale]?: string }`, which falls back to `en`. Content can be translated later without changing the schema.

## Money

- The home currency is EUR, and every total is in EUR cents (integers, so there are no floating-point errors).
- Each trip has a `localCurrency` field.
- An expense is stored as `{ amountMinor, currency, rateToEur?, paidBy, splitWith[], date }`. `rateToEur` is required whenever `currency` isn't EUR, and zod enforces this.
- The stored rate means past totals never drift. `CurrencyConverter` fetches today's rate live and only appears for trips whose currency isn't EUR, so Paris doesn't show it.
- If Frankfurter is down, the converter shows "rate unavailable" and the budget still works, because it relies only on stored rates.
- I'll check the Frankfurter endpoint and response shape against its docs during the build.

## Paris content (first trip)

- **Itinerary:** six days. New Year's Eve gets its own card (Champs-Élysées / Trocadéro, transport, crowds). Cards for 31 Dec and 1 Jan carry closure notes.
- **Info:**
  - Getting in from CDG and Orly: RER B, metro line 14, Roissybus.
  - Tickets and the airport fare.
  - Weather.
  - What is open or closed on 31 Dec and 1 Jan.

  - "Where to stay" inside the Périphérique.

## Privacy / security (public repo + public site)

- Only the area goes in the repo. Booking addresses, confirmation codes and phone numbers never do. `CLAUDE.md` and `CONTRIBUTING.md` both state this rule.
- ⚠️ **Budget amounts and travellers' names will be public.** Use first names or nicknames. If that becomes a problem, the Budget page is the first thing to move behind a Firebase login.
- There are no secrets. Frankfurter needs no API key.
- External data is untrusted: the Frankfurter response is validated with zod, and the CSP allows only that one origin.
- The GitHub Actions are pinned by SHA, and Dependabot is on.
- `robots.txt` blocks crawlers and the pages carry a `noindex` meta tag, so the site stays out of search engines.
